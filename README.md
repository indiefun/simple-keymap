# 轻映 · 简单按键映射器

免费开源的 Windows x64 桌面小工具，用 Go 和原生 Win32 编写。用一个键替代另一个键，无需安装驱动或系统服务。

官网：<https://qingying.luming.host/> · [下载最新版](https://github.com/indiefun/simple-keymap/releases/latest) · [问题反馈](https://github.com/indiefun/simple-keymap/issues) · [GPL-3.0 许可](LICENSE)

应用图标采用两枚叠放键帽与映射箭头，源文件和多尺寸 Windows 图标见 `assets`。图标已嵌入程序，重新编译会自动包含。

## 使用

下载便携版 ZIP，**全部解压**到同一个文件夹，双击 **`SimpleKeymap.exe`**。同目录的 `SimpleKeymap.Input.exe` 是配套文件，请保留，不用单独打开。自行构建的打包文件统一在 `dist`。

1. 点击「添加第一条映射」，在独立窗口中依次选择**你实际按哪个键 → 让它代替哪个键 → 确认效果**。也可以从「侧键 → 中键」示例开始，确认后才创建。
2. 点击「添加并启用」，**切到其他应用试按**。主界面列出已有映射，左侧开关控制单条规则，右侧可直接修改和删除。
3. 修改直接进入效果确认页，点击「更换」调整需要改的按键，再「保存修改」。取消不改变原规则；有未保存更改时可选择继续编辑。
4. 「映射总开关」控制全部映射并保留各条启用选择；开关左侧显示 `Ctrl + Alt + F12` 暂停 / 恢复快捷键。删除后可撤销；方向键选择规则，F2 修改，Delete 删除。

选键时可以明确点击录入后按下并松开一个键，也能从可搜索、可按鼠标 / 键盘分类的列表选择。Esc 取消录入，8 秒后自动结束；按住尚未释放时不完成录入，避免误触发下一步。目标按键损坏或需要 Esc 时也可从列表选择。

原按键已有规则时，显示已有映射并提供「修改已有映射」。新建和修改先保存再更新；失败时窗口保留草稿及重试入口，原规则不变。快捷开关等即时更改保存失败时持续提示「尚未保存」，可手动重试。录入期间临时暂停，完成或取消后恢复此前状态。

顶部提供「关于与许可」「支持与反馈」「检查更新」。「支持与反馈」直接打开官网对应区域；使用说明和诊断信息收在「关于与许可」中。许可窗口内置 GPL 全文与品牌说明，离线可读，并可打开本版本源码。

「检查更新」展示当前版本、检查结果和下载入口，可勾选「启动时检查更新」，默认关闭。开启后，启动时在后台查询 GitHub 最新正式版，有新版时在顶部提示。更新检查不包含映射规则或按键记录；下载和替换由用户操作。检查失败可重试，或直接前往官网选择加速下载。

映射完全跟随原按键的按下和抬起：

| 实际操作 | 模拟操作 |
| --- | --- |
| 按下侧键 1 | 按下鼠标中键 |
| 一直按住侧键 1 | 中键一直保持按下 |
| 抬起侧键 1 | 抬起鼠标中键 |
| 再次按下、抬起侧键 1 | 再次按下、抬起中键 |

不是切换开关，不是只发送按下，也不会在按下时自动补一个抬起。鼠标右键的按下 / 抬起不改变侧键到中键的映射。侧键原来的后退动作会被拦截；模拟输入不会递归触发另一条规则。

配置窗口内暂不执行映射，方便操作；切到其他程序后生效。最小化后继续映射，关闭窗口停止监听并退出。正常退出会丢弃积压操作，仅释放已经模拟按住的键。

配置自动保存到 **`SimpleKeymap.exe` 同目录的 `config.json`**，迁移时复制整个软件文件夹即可带走规则、总开关、单条开关和更新偏好。底部使用一条状态栏显示操作结果或保存错误。

同目录没有 `config.json` 时，首次启动会创建默认配置。请将软件放在可写目录；创建失败时会提示并暂停映射。配置读取失败时保留原文件，方便检查或恢复。

升级时关闭旧版，将新版完整解压到原软件目录，保留 `config.json`；若改用新文件夹，请一并复制原来的 `config.json`。发布包不携带用户配置，不会用空白配置覆盖已有设置。

## 异常与退出

模拟输入只在独立辅助进程里发送，主程序不会回退为自己发送。缺少辅助文件或版本不匹配会提示退出。

发送和通信共用 750ms 超时。超时或发送失败后自动暂停，丢弃后续输出，不重试、不反复拉起辅助进程。主窗口可继续操作和关闭。关闭等待有时限；辅助进程绑定到主进程的 Windows Job，主进程被强制结束时也会请求结束辅助进程。

曾在本机发现 Windows `NtUserSendInput` 卡在内核中，连独立程序的零距离输入也被阻塞。这种情况可能导致一个辅助进程残留到重启，即使请求终止也无法立即清除；Go 程序不能保证恢复 Windows 内核。若出现「Windows 输入发送超时」，请保存工作并重启 Windows，不要反复开启映射。

## 支持范围

- 鼠标左键、右键、中键、侧键 1 / 2。
- 字母、数字、F1–F12、常用编辑键、方向键、左右 Ctrl / Shift / Alt、常用符号、小键盘、媒体键。
- 仅单个键到单个键；没有组合键、宏、连点、滚轮滚动或应用专属规则。
- 鼠标驱动需要把侧键作为标准前进 / 后退按钮输出。
- 目标程序以管理员运行时，轻映需要相同权限。部分游戏或受保护程序可能不接受模拟输入。

## 编译

Windows x64，Go 1.23 或更新版本；无第三方 Go 依赖，不需要 C 编译器。

```powershell
.\build.ps1
# 或指定版本，GitHub Release 也使用同一脚本：
.\build.ps1 -Version 1.2.1
```

脚本运行测试和 `go vet`，随后结束**本工程目录内**正在运行的轻映及输入辅助进程，重新生成 `dist` 内的两个 exe、`SimpleKeymap-v1.2.1-windows-x64.zip` 和同名 `.sha256` 校验文件。版本默认取 `VERSION`，也可用 `-Version` 指定；标题栏、关于窗口和包内说明都包含版本号。打包后自动核对 ZIP 内容、许可文件、对应版本源码链接、exe 内置版本和校验和。不会结束其他目录里的同名程序。测试或构建失败会报错。Go 不在 PATH 时使用工程内 `.tools/go/bin/go.exe`。

仅检查、不打包、不结束正在使用的程序：

```powershell
.\build.ps1 -TestOnly
```

## 自动打包与发布

普通推送和 PR 会运行 Windows 程序测试、`go vet`、网站资源与浏览器检查，不发布程序。发布新程序时，更新 `VERSION` 并提交，然后推送同一版本的标签：

```powershell
git push origin main
git tag v1.2.1
git push origin v1.2.1
```

`.github/workflows/release.yml` 仅响应 `v主版本.次版本.修订号` 标签，要求与 `VERSION` 一致，并从同一标签生成程序 ZIP、完整源码 ZIP 及各自 SHA256，然后创建 GitHub Release。发布说明放在 `.github/release-notes/v版本号.md`。使用 GitHub 提供的 `GITHUB_TOKEN`，无需自行配置发布密钥。程序 ZIP 内保留稳定的两个 exe 文件名及许可、版权和品牌说明，方便用户覆盖升级。

网站继续由 Cloudflare 跟踪 `main` 自动更新；发布程序不需要修改网站的下载链接，`releases/latest` 会指向最新版本。发布 Action 还会上传内容相同的 `SimpleKeymap-windows-latest.zip` 和对应 SHA256，供官网通过 `gh-proxy.com` 提供国内加速下载；页面保留 GitHub Release 备用入口。
